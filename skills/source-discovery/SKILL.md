# Source discovery

Start from the questions and claims to resolve. Read existing references and
reading copies before repeating discovery. Prefer the source that owns the claim:
a paper for a published method, implementation for code behavior, and recorded
runtime evidence for what actually executed. These answer different questions.

1. Define the bounded questions, known sources, desired edition and unresolved
   conflicts. Record whether absence means not found in this search or a supported
   statement about the source's full coverage.
2. Inspect accessible sources directly. Record title, author/owner, stable URL or
   identifier, edition/revision, source date, retrieval date and access restriction.
   Missing metadata stays unknown. Keep source dates distinct from access dates.
3. When a source requires an existing signed-in browser or GUI, use the client's
   supported browser/computer tools and their access rules. If unavailable, hand
   the user or GUI session the exact questions and links. Do not invent a reading
   or request credential/session-cookie exports.
4. Capture findings with section, printed page, equation, table or code-revision
   pinpoints. Separate direct observations, interpretation and proposed actions.
   Verify OCR/extracted text against the source where symbols or layout matter.
5. Return the [source handoff](references/source-handoff.md): findings,
   metadata, conflicts, unread sources and next checks. Retain only the excerpts
   needed for the task; source copies keep their access and redistribution limits.
6. Use [source-library](../source-library/SKILL.md) to reconcile citation entries.
   A receiving agent checks claim support and version before changing conclusions.

Do not call a secondary summary a reading of its cited original. Search results,
agent memory and chat transcripts are leads, not substitutes for inspecting the
evidence. Delivery of findings does not establish their scientific acceptance.
